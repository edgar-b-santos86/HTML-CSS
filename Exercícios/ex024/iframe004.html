Iframes seguros

Iframes são elementos HTML que permitem incorporar conteúdo de outra página web dentro da página atual. Eles podem ser úteis para exibir conteúdo externo, mas também podem representar riscos de segurança se não forem usados com cautela.

Nesta aula vamos aprender a como deixar nossa página um pouco mais segura fazendo a utilização dos iframes.

Exemplo:

Vamos criar um arquivo chamado pag001.html dentro da pasta paginas, e dentro desse arquivo vamos colocar o seguinte código de um formulário simples e vamos aplicá-lo no iframe:

O código do iframe acima ficou assim:

<iframe src="paginas/pag001.html" width="400px" height="150px"></iframe>

Como podemos ver acima colocamos um iframe com um formulário simples de cadastro do nome, entretanto, como foi explicado pelo professor Gustavo Guanabara, isso pode representar um risco de segurança pois ao colocarmos um iframe para um site do qual não conhecimos, podemos estar sujeitos a ataques e também a deixar que dados dos usuários dos nossos sites sejam comprometidos.

Neste momento, como você pode perceber é possível colocar nosso nome e enviar o formulário clicando no botão cadastrar.

Para evitar que isso aconteça, podemos colocar o atributo sandbox com o valor sandbox dentro do iframe, e com isso, o formulário não irá funcionar, ou seja, não será possível enviar os dados do formulário para o servidor, e isso é uma medida de segurança importante para proteger os usuários de possíveis ataques.

Abaixo faremos a confirguração de segurança sandbox para ver o resultado:

O código acima ficou assim:

<iframe src="paginas/pag001.html" width="400px" height="150px" sandbox="sandbox" referrerpolicy="no-referrer"></iframe>

Se o site for confiável ou mesmo for um site de nossa propriedade, podemos considerar algumas exceções e utilizar configurações dentro do atributo sandbox para permitir que certas funcionalidades sejam habilitadas.

Por exemplo, se quisermos permitir que o formulário funcione normalmente, podemos usar a configuração allow-forms dentro do atributo sandbox, e com isso, o formulário irá funcionar normalmente, mas ainda assim, outras funcionalidades que possam representar riscos de segurança estarão desabilitadas.

Existem as seguintes opções para o atributo sandbox:

  • allow-forms: Permite que o formulário funcione normalmente.
  • allow-same-origin: Permite que o iframe acesse recursos do mesmo origin.
  • allow-scripts: Permite que scripts sejam executados dentro do iframe.
  • allow-top-navigation: Permite que o iframe navegue para o topo da página.
  • allow-popups: Permite que o iframe abra pop-ups.
  • allow-downloads: Permite que o iframe inicie downloads.
  • allow-orientation-lock: Permite que o iframe bloqueie a orientação da tela.
  • allow-pointer-lock: Permite que o iframe bloqueie o ponteiro do mouse.
  • allow-popups-to-escape-sandbox: Permite que pop-ups abertos pelo iframe escapem das restrições do sandbox.
  • allow-top-navigation-by-user-activation: Permite que o iframe navegue para o topo da página apenas quando o usuário interagir com o conteúdo do iframe.
  • allow-storage-access-by-user-activation: Permite que o iframe acesse o armazenamento apenas quando o usuário interagir com o conteúdo do iframe.
  • allow-credentials: Permite que o iframe acesse credenciais de autenticação.
  • sandbox: Aplica as restrições do sandbox ao iframe.

Além disso podemos configurar o atributo referrerpolicy, com isso controlar as informações que são coletadas/enviadas pela nossa página.

O valor padrão para o atributo referrerpolicy é no-referrer, o que significa que nenhuma informação de referência será enviada ao acessar o conteúdo do iframe.

Existem as seguintes opções para o atributo referrerpolicy:

  • no-referrer: Nenhuma informação de referência será enviada.
  • no-referrer-when-downgrade: A informação de referência será enviada apenas para conexões seguras (HTTPS).
  • origin: Apenas a origem da página será enviada como referência.
  • origin-when-cross-origin: A origem da página será enviada como referência apenas para conexões seguras (HTTPS).
  • same-origin: A informação de referência será enviada apenas para conexões do mesmo origin.
  • strict-origin: A origem da página será enviada como referência apenas para conexões seguras (HTTPS) e do mesmo origin.
  • strict-origin-when-cross-origin: A origem da página será enviada como referência apenas para conexões seguras (HTTPS) e do mesmo origin, e nenhuma informação de referência será enviada para conexões inseguras (HTTP).
  • unsafe-url: A informação de referência será enviada para todas as conexões, independentemente do protocolo de segurança.
